    Expressions and evaluation#

    SymJ.SymJ

    source 
    SymJ

    Symbolic manipulation with a single concrete, hash-carrying node type, eager canonicalization of sums, products and powers, exact numbers, and support for the TermInterface v2 contract. See docs/src/design/ for the design.

    SymJ.@syms

    source 
    @syms x y f()
@syms xs[1:10] A[0:2, 0:2] fs[1:3]()

    Create symbols (and, with f(), a SymFunction) and bind them to the names. xs[r₁, r₂, …], with ranges (evaluated where the macro is called, so xs[1:n] works), binds an array of symbols named by their indices: @syms xs[0:3] gives the vector [xs₀, xs₁, xs₂, xs₃] (indexed from 1 as usual; the offset is in the names), and A[1:2, 1:2] a matrix of A₁_₁, A₁_₂, …. fs[1:3]() gives functions. The names may also be separated by commas, @syms x, y.

    SymJ.symbols

    source 
    symbols("x y z")

    A tuple of symbols named by a space- or comma-separated string.

    SymJ.Sym

    source 
    Sym

    A symbolic expression. Construct leaves with Sym(:x), Sym(2), Sym(1//3), Sym(π), or the @syms macro; build compound expressions with the usual arithmetic operators and functions. Expressions are kept in a canonical form as they are built: like terms are collected in sums, like bases are collected in products, and numeric powers such as sqrt(Sym(8)) are reduced exactly (to 2*sqrt(2)).

    Layout by kind:

    kind num args exps coefs
    NUMBER the value
    SYMBOL
    CONSTANT
    ADD constant term terms (sorted) coefficient of each
    MUL coefficient bases (sorted) exponent of each
    POW [base, exponent]
    FN arguments

    name holds the symbol, constant, or function name. The vectors must never be mutated once a node is built; nodes share them freely.

    SymJ.subs

    SymJ.AbstractSymbolic

    source 
    AbstractSymbolic <: Function

    Supertype of SymJ's symbolic objects. Symbolic objects are callable, and calling a SymFunction builds an unevaluated function application. An expression ex can be called in these ways:

    • ex(a) with a number a: evaluates ex, which may have one free variable, with Julia's arithmetic on a (see evaluate), so (x^2)(3) === 9. With a symbolic a, it substitutes instead.

    • ex(x => a, y => b): substitutes (see subs) and returns an expression.

    • ex(; x = a, y = b): gives values to the variables named x and y. If every one of ex's variables gets a non-symbolic value, ex is evaluated with Julia arithmetic and the result is a Julia number: (x^2 + y)(; x = 2, y = 3) === 7. Otherwise this substitutes and returns an expression: (x^2 + y)(; x = 2) == y + 4. Names that are not in ex are ignored, so one set of keywords can be used for several expressions. Keywords can't be combined with the other forms.

    • ex(): the value of a constant expression as a Julia number, or ex itself if it has a free variable.

    SymJ.SymNumber

    source 
    SymNumber <: Real

    Numeric scalar used inside symbolic expressions. It is exact (an integer or rational of arbitrary size) unless constructed from a floating point value. Small values never allocate; arithmetic promotes to BigInt on overflow and demotes back when results fit.

    SymJ.Relation

    source 
    Relation

    A symbolic equation or inequality between two expressions: x^2 + 1 ~ 3, x ≪ 1 (Lt(x, 1)), x ≦ 1, x ≫ 1, x ≧ 1, x ≶ 1 (Ne). See lhs, rhs.

    Calling a relation substitutes into both sides, as calling an expression does ((x^2 ~ 4)(x => 2), (x^2 ~ 4)(2)); when no symbols remain the result is a Bool. r() evaluates a relation between constants.

    Base.rationalize — Tuple{Sym}

    source 
    rationalize(ex::Sym; tol = nothing)
rationalize(T, ex::Sym; tol = nothing)

    ex with each floating-point number in it replaced by a nearby rational (rationalize(T, f; tol) from Julia, each float's own eps when tol is not given): rationalize(0.5x + 1.25) is x/2 + 5/4. Exact numbers are left alone. The result has only rationals, not recognized constants such as √2 or π.

    SymJ.coeff — Union{Tuple{Any, Sym}, Tuple{Any, Sym, Any}}

    source 
    SymJ.coeff(ex, x, n = 1)
SymJ.coeff(ex, x^n)

    The coefficient of x^n in ex, after expanding: the sum of the factors that multiply x^n exactly in its terms, so coeff(a*x^2 + b*x + c, x) is b and n = 0 gives the terms free of x. Terms with x in some other way (sin(x)) are not counted. x may be a symbol or a function call (y(t)), and n any power, -1 or 1/2 too. Not exported.

    @syms a b c x y
SymJ.coeff(a*x^2 + b*x + c, x, 2)           # a
SymJ.coeff((x + y)^3, x^2)                  # 3y
SymJ.coeff(a*x + sin(x) + b, x, 0)          # b

    SymJ.evaluate — Tuple{Sym, Any}

    source 
    evaluate(ex, a)

    Evaluate ex, which may have at most one free symbol, at a using Julia arithmetic on a. This is what calling an expression on a non-symbolic value does: if u = x^2 then u(3) === 9, u(3.0) === 9.0 and u(1//2) === 1//4. Because the arithmetic is generic, a may be any number type (big floats, dual numbers, intervals, ...).

    • Exact coefficients are used as Julia integers and rationals, so exact inputs give exact results where Julia arithmetic would ((x/3)(3) == 1//1).

    • When a is a floating point type (real or complex), constants such as 1/3, sqrt(2) and π are computed in that type, so BigFloat inputs keep their precision.

    • Negative integer powers use inv ((1/x)(2) === 0.5), and a negative base with a fractional power gives the principal complex value (sqrt(x)(-4) == 2im).

    • Functions need a Julia method (registered with julia = ...); user functions without one throw an ArgumentError.

    SymJ.gather — Tuple{Any, Sym}

    source 
    SymJ.gather(ex, x)
SymJ.gather(ex, [x, y, ...])

    ex expanded and its terms gathered by powers of x (by monomials in x, y, ... for several): a*x^2 + b*x^2 + a*x - b*x + c as (a + b)*x^2 + (a - b)*x + c. Terms with x in some other way (sin(x)) are left as they are. (SymPy's collect; Julia's collect is another function.) Not exported.

    @syms a b c x y
SymJ.gather(a*x^2 + b*x^2 + a*x - b*x + c, x)    # (a + b)*x^2 + (a - b)*x + c
SymJ.gather(x*y + a*x*y + x + b*y, [x, y])       # (a + 1)*x*y + x + b*y

    SymJ.horner — Tuple{Any, Sym}

    source 
    SymJ.horner(p, x)
SymJ.horner(p, [x, y, ...])
SymJ.horner(p)

    The polynomial p in nested (Horner) form in x: 2x^3 - x + 5 as (2x^2 - 1)x + 5 (((2x)x - 1)x + 5, a run of zero coefficients as one power), so it evaluates with the fewest multiplications. With several variables (all of p's, in order, when none are given), each coefficient is put in Horner form in the next ones. The coefficients may be any expressions free of the variables. Julia's evalpoly evaluates numbers this way. Not exported.

    @syms x y
SymJ.horner(2x^3 - x + 5, x)                  # (2x^2 - 1)*x + 5
SymJ.horner(x^2*y + x*y^2 + x + 1)            # x*(x*y + y^2 + 1) + 1

    SymJ.unwrap_const — Tuple{Any}

    source 
    SymJ.unwrap_const(x)

    The value of a constant expression as a Julia number, and anything else as it is: ex() as a function, for map and other generic code (as unwrap_const in SymbolicUtils, SymEngine and Giac). Exact values stay exact: SymJ.unwrap_const(Sym(1)/2) === 1//2, SymJ.unwrap_const(PI) === π, SymJ.unwrap_const(sqrt(Sym(2))) === sqrt(2); an expression with a free symbol and a non-Sym argument are returned unchanged. Not exported.

    map(SymJ.unwrap_const, [Sym(2), x + 1, Sym(3)/4])   # Any[2, x + 1, 3//4]

    SymJ.nsimplify — Tuple{Any}

    source 
    SymJ.nsimplify(ex; constants = (), tol = 1e-14, maxcoeff = 1000, maxdegree = 4)

    ex with its floats replaced by exact numbers that match them, as SymPy's nsimplify. Each float is recognized, in this order, as

    • a rational with small numerator and denominator (0.75 = 3/4);

    • a rational combination of the constants (exact numbers such as pi, ℯ, sqrt(Sym(2)), log(Sym(2))) with small coefficients (7.283185307179586 = 1 + 2π with constants = [pi]);

    • a root of an integer polynomial of degree at most maxdegree with small coefficients, given in radicals (or as solve gives it) (1.4142135623730951 = √2, 1.618033988749895 = (1 + √5)/2).

    tol is the relative error allowed; a float typed to fewer digits needs a larger tol (SymJ.nsimplify(1.414214; tol = 1e-6) is √2). A relation (with coefficients at most maxcoeff) is accepted only when its coefficients are small enough that it is unlikely to hold to within tol by chance, so a float that is not recognized is left as it is. To write every float as a rational, use rationalize. Not exported.

    SymJ.nsimplify(0.5x + 1.4142135623730951)              # x/2 + √2
SymJ.nsimplify(2.0943951023931953; constants = [pi])   # 2π/3
SymJ.nsimplify(1.2599210498948732)                     # 2^(1/3)
SymJ.nsimplify(3.0 + 2.718281828459045im; constants = [ℯ])   # 3 + ℯ*im

    SymJ.cse — Tuple{Any}

    source 
    SymJ.cse(ex; prefix = :t)

    Common subexpression elimination: (replacements, reduced), with replacements a vector of t1 => s1, t2 => s2, ... (each s in terms of the earlier ts) and reduced the expressions with the repeated parts replaced. ex is an expression or a vector (tuple) of them, and reduced has the same shape. A subexpression is repeated when the same node (a sum, product, power or function call, a power also as a factor of a product) occurs more than once; a part of a larger sum or product (x + y inside x + y + z) is not separated out. The names avoid the symbols in ex. Not exported.

    @syms x y
SymJ.cse((x + y)^2 + sin(x + y))      # ([t1 => x + y], t1^2 + sin(t1))

    SymJ.lambdify — Tuple{Any, Vararg{Sym}}

    source 
    lambdify(ex, vars...)
lambdify(ex, vars::Union{Tuple,AbstractVector})
lambdify(ex)

    Compile ex into a Julia function of the symbols vars, in that order. With no vars, ex may have at most one free variable. ex may also be an array or tuple of expressions, and the function then returns an array of the same shape (or a tuple), with common subexpressions shared between the entries.

    The function computes what calling the expression computes, at the speed of compiled Julia code: lambdify(x^2 + 1)(3) === 10, and lambdify(sin(x) * y, x, y)(1.0, 2.0). Arguments may be any number type (BigFloat, dual numbers, intervals, ...).

    A function of several variables can also be called with them in one tuple or vector, f((1.0, 2.0)); calling it with the wrong number of values is an error.

    lambdify_expr gives the generated Julia expression.
